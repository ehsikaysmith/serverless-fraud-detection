# Serverless Fraud Detection Platform

A serverless, event-driven fraud detection platform that scores card transactions in near real-time using rule-based checks and an Isolation Forest ML model on Lambda. Transactions flow through an HTTP API to an SQS-decoupled scoring pipeline. Flagged transactions are stored in DynamoDB with AI-generated explanations from Amazon Bedrock, and high-risk alerts go via SNS. All raw and scored data lands in S3 in Parquet format, queryable through Glue Data Catalog and Athena for fraud pattern analytics. CloudWatch provides dashboards and alarms across all components.

> **What this is:** a starting point generated by AWS Architecture Advisor: the architecture as a
> CloudFormation template, sample code that proves each service works, and scripts to deploy, test and
> remove it. It is not a finished application. Build your features on it with the editor and tools you
> prefer; [docs/EXTENDING.md](docs/EXTENDING.md) shows where things go and what each change costs.

## Cost

Estimated **$10.44/month** with the usage assumed in [ARCHITECTURE.md](ARCHITECTURE.md), where each service's estimate is listed.

Already chosen to keep it low:

- Lambda functions on Arm (arm64), about 20% cheaper than x86, billed only while they run
- an HTTP API, the cheaper kind of API Gateway, billed per request
- DynamoDB on-demand: no charge for idle capacity
- logs kept for 14 days, not forever
- dead-letter queues, so failing messages are kept instead of retried forever

Set an [AWS Budget](https://console.aws.amazon.com/billing/home#/budgets) with an email alert, and remove the
stack when you no longer need it (`bash scripts/destroy.sh`).

## Quick start

You need **Node.js 20+**, the **AWS CLI v2**, AWS credentials (`aws configure` or `aws sso login`)
and bash (on Windows: Git Bash, or use `scripts\deploy.ps1` in PowerShell).

```bash
bash scripts/deploy.sh
bash scripts/smoke-test.sh
```

`deploy.sh` builds the code, uploads it to a private deployment bucket, deploys
`infrastructure/template.yaml` with CloudFormation and prints the stack outputs (URLs, names). Choose the
name and region with `STACK_NAME=my-app AWS_REGION=eu-west-1 bash scripts/deploy.sh` (keep the name
under 30 characters, and pass the same values to the other scripts).

`smoke-test.sh` then checks the deployed stack really works: it calls the API, runs every sample
route, sends a real message to every trigger and follows it through the connected services, then
removes its test data. It prints one line per check.

### Set up by hand

- Connection processing-queue → dead-letter-queue (sqs->sqs) is shown in the design but not wired automatically.
- Bedrock Explainer calls Amazon Bedrock (Claude 3 Haiku) (external): store its API key or credentials in AWS Secrets Manager, read them at runtime, and call the provider's API over HTTPS.
- Amazon Athena (external) sends data to Transactions Data Lake: connect them using the provider's integration for AWS (for example a webhook through API Gateway or an EventBridge partner event source).
- AWS Glue Data Catalog (external) sends data to Transactions Data Lake: connect them using the provider's integration for AWS (for example a webhook through API Gateway or an EventBridge partner event source).
- Some resources are named after the stack, so keep the stack name under 30 characters.

## What the API does

Sample routes, one small real action per connected service. Replace them with your own.

| Route | Does | Function |
|---|---|---|
| `GET /ingest-function/health` | Health check (public) | Transaction Ingest |
| `POST /ingest-function/processing-queue/messages` | Send the JSON body to Processing Queue | Transaction Ingest |
| `GET /query-function/health` | Health check (public) | Query Flagged Transactions |
| `POST /query-function/flagged-table` | Save the JSON body as a new item in Flagged Transactions Table | Query Flagged Transactions |
| `GET /query-function/flagged-table/{id}` | Read an item back | Query Flagged Transactions |
| `DELETE /query-function/flagged-table/{id}` | Delete an item | Query Flagged Transactions |

The API address is the `...Url` stack output.

## Develop

Code is in TypeScript (Node.js 22): `functions/ingest-function/index.ts`, `functions/scoring-function/index.ts`, `functions/explainer-function/index.ts`, `functions/query-function/index.ts`.

```bash
npm install
npm run typecheck
npm test
npm run build
```

The helpers at the top of each file call the connected AWS services using the names the template
passes in as environment variables, so you can replace the samples with your own logic straight away.

## Check before you deploy

```bash
bash scripts/check.sh
```

The same checks AWS Architecture Advisor ran (in AWS CodeBuild) before you could download this kit:
cfn-lint on the template, shell script syntax, the type-check, unit tests, the build, a vulnerability
audit of runtime dependencies, and the CDK app synthesized and compared with the template.

## Optional: the same infrastructure as an AWS CDK app

CloudFormation (`infrastructure/template.yaml`) is the default and all you need. If you'd rather grow
the infrastructure in TypeScript code, `cdk/` creates exactly the same resources (the checks prove it):

```bash
npm install --no-audit --no-fund
npm run build   # builds the code into build/, which the CDK app deploys
cd cdk
npm install
npx cdk bootstrap   # once per account and region
npx cdk deploy
```

Pick one: deploy a stack with `scripts/deploy.sh` or with CDK, not both, and delete the other if you
no longer need it.

## Remove everything

```bash
bash scripts/destroy.sh
```
